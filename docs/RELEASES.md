# Building and distributing Browser C

## Automated packages

The `Linux packaged build smoke` workflow builds AppImage and Debian packages on pull requests and pushes to `main`, stages and validates checksums, installs the Debian package into a clean Ubuntu runner, and runs the packaged browser's Electron UI/navigation/privacy/recovery smoke suite under Xvfb. It also extracts the AppImage without FUSE and runs the same smoke suite against its packaged launcher. It uploads a short-lived CI artifact for review. These CI checks do not replace manual installation and hands-on testing on Fedora or other target systems. The `Desktop packages` workflow runs when a `v*` tag is pushed or when manually dispatched from GitHub Actions. It creates platform-specific build artifacts:

- Linux: AppImage and Debian package
- Windows: NSIS installer
- macOS: DMG and ZIP

Each platform job uses the committed npm lockfile with `npm ci`, runs `npm audit --audit-level=high`, repository validation, syntax checks, and automated tests, then builds packages with Electron Builder. A staging step copies only the expected distributable package formats into `release/artifacts`, excluding unpacked application directories and builder intermediates. The workflow rejects empty packages, generates a `SHA256SUMS.txt` manifest, and checks that required formats exist, rejects unexpected or cross-platform artifact types, and requires every staged artifact to be listed exactly once with a matching SHA-256 digest. Only the staged packages and checksum manifest are attested and uploaded. Workflow artifacts are retained for 14 days and are not the same as a published GitHub Release.

## Verify downloaded artifacts

Keep the package and its `SHA256SUMS.txt` file together. From a Linux/macOS terminal, run:

```sh
sha256sum --check SHA256SUMS.txt
```

On Windows PowerShell, verify a named file by comparing its digest with the corresponding line in `SHA256SUMS.txt`:

```powershell
Get-FileHash .\Browser-C-0.2.0-win32-x64.exe -Algorithm SHA256
```

Use the actual filename produced by the workflow. A checksum detects accidental corruption or mismatches; it does not prove who built a package or protect against an attacker who can replace both the package and its manifest.

When the GitHub CLI is installed and authenticated, verify the build-provenance attestation for a downloaded artifact with:

```sh
gh attestation verify ./Browser-C-0.2.0-linux-x64.AppImage --repo Liladizilla/browser-c
```

Replace the example path with the exact artifact you downloaded. Repeat for each package you intend to trust. A successful attestation verifies provenance against GitHub's attestation service and repository identity; it does not certify that the application is bug-free, safe to install, signed by an OS vendor, or successfully tested on your machine.

## Release gates and limitations

- Workflow artifacts are build outputs for testing, not stable public releases.
- Linux packaging CI now installs the Debian package and launches the packaged browser, then runs the real Electron UI smoke suite under Xvfb; it also runs the same suite against the extracted AppImage payload. The suite covers browser-chrome rendering, tab creation and keyboard switching, narrow-window layout, library-panel accessibility/focus behavior, navigation controls, redirects, failed-navigation recovery, private-session isolation, and renderer-crash recovery against local fixtures. This still does not replace hands-on testing on Fedora, nor testing downloads, media, GPU behavior, upgrade/uninstall behavior, or platform-specific integration.
- macOS signing/notarization, Windows code signing, published SBOM, clean-install/upgrade testing, and installed-app launch/navigation smoke tests on Windows and macOS remain future release gates. GitHub build-provenance attestations are generated by the packaging workflow but still require a real packaging run and independent verification. Artifact validation confirms package presence and file integrity, not successful installation or runtime behavior.
- Do not advertise an artifact as a stable release until platform launch and security checks are complete.
